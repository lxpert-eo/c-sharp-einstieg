Überblick

Worum es geht und wie die Einheit aufgebaut ist.

Ein Programm läuft von oben nach unten, eine Zeile nach der anderen. Das reicht für wenig. Sobald ein Programm auf Eingaben reagieren, Dinge wiederholen oder mit Fehlern klarkommen soll, brauchst du mehr. Genau darum geht es hier.

  • if elseDas Programm entscheidet: Läuft Block A oder Block B?
  • switch caseEin Wert wird mit mehreren festen Möglichkeiten verglichen.
  • SchleifenEin Stück Code läuft mehrmals. Es gibt while, do while, for und foreach.
  • TryParseAus Text eine Zahl machen, ohne dass das Programm abstürzt.
  • Try CatchEin Fehler soll das Programm nicht beenden. Du fängst ihn ab.
  • StruktogrammEin Ablauf als Bild aus Kästen. So planst du, bevor du Code schreibst.
MerkbildEntscheiden, wiederholen, absichern. Mehr braucht ein Programm für den Anfang nicht.

Grundlagen

Variablen, Rechnen, Vergleiche, Eingabe und Ausgabe.

Bevor es um Entscheidungen und Schleifen geht, brauchst du ein paar Grundlagen. Die meisten kennst du vielleicht schon. Hier als kurzer Block zum Nachschlagen.

Variablen

Eine Variable ist ein Platz im Speicher mit einem Namen. Du legst einen Wert hinein und kannst ihn später wieder lesen oder ändern. Vor dem Namen steht der Datentyp. Er sagt, was für ein Wert hineinpasst.

DatentypWas passt hineinBeispiel
intGanze Zahlenint alter = 17;
doubleKommazahlen. Im Code mit Punkt geschrieben.double preis = 4.5;
stringText in Anführungszeichenstring name = "Anna";
boolWahr oder falschbool volljaehrig = true;
charEin einzelnes Zeichenchar buchstabe = 'A';
int alter = 17;
double preis = 4.5;
string name = "Anna";
bool volljaehrig = alter >= 18;
Console.WriteLine(name + " ist " + alter + " Jahre alt.");

Das einzelne Gleichheitszeichen heißt hier nicht gleich, sondern speichere. Rechts steht der Wert, links der Platz, in dem er landet. Im Pseudocode zeigt dafür ein Pfeil: alter ← 17.

Struktogramm

Abläufe als Bild: Bausteine, lesen, zeichnen, in Code umsetzen.

Ein Struktogramm zeigt einen Ablauf als Bild. Es besteht aus Kästen, die du von oben nach unten liest. Es gibt keine Pfeile. Programmierer zeichnen es, bevor sie Code schreiben, damit sie vorher wissen, was das Programm tun soll. Der andere Name ist Nassi Shneiderman Diagramm.

  • Ein KastenEin Schritt. Meist eine Zeile Code.
  • Von oben nach untenDu liest in dieser Reihenfolge.
  • IneinanderSchleifen und Verzweigungen enthalten weitere Kästen.

Ein Beispiel lesen

Die Klasse bestellt Pizza. Eine Pizza kostet 8 Euro. Wer zehn oder mehr bestellt, bekommt zehn Prozent Rabatt. Wie viel muss die Klasse zahlen?

ENDE WENN

else

Vom Struktogramm zum Code

  • 1Lies das Struktogramm einmal ganz durch.
  • 2Ein Kasten wird eine Zeile.
  • 3Ein Dreieck wird zu if und else. Links steht Ja, rechts steht Nein.
  • 4Eine Schleife wird zu for, foreach, while oder do while. Was im Kasten daneben steht, kommt in die geschweiften Klammern.
  • 5Eingabe und Ausgabe werden zu Console.ReadLine und Console.WriteLine.

if else

Das Programm entscheidet: zwei und mehr Möglichkeiten.

Mit if else lässt du dein Programm entscheiden. Es prüft eine Bedingung. Ist sie wahr, läuft der erste Block. Ist sie falsch, läuft der zweite, den else einleitet. Ein else ist optional.

Pseudocode
WENN alter >= 16 DANN
    AUSGABE "Viel Spaß im Kino"
SONST
    AUSGABE "Erst ab 16"
ENDE WENN
C#
int alter = 15;
if (alter >= 16)
{
    Console.WriteLine("Viel Spaß im Kino");
}
else
{
    Console.WriteLine("Erst ab 16");
}
  • Die BedingungSteht in runden Klammern hinter if. Sie muss true oder false ergeben.
  • Der BlockSteht in geschweiften Klammern. Nur wenn die Bedingung stimmt, läuft er.
  • elseLäuft in allen anderen Fällen. Es hat keine eigene Bedingung.

Mehrere Möglichkeiten mit else if

Gibt es mehr als zwei Fälle, hängst du else if an. C# prüft von oben nach unten. Der erste Treffer gewinnt, danach wird nichts mehr geprüft.

else if (punkte >= 75)
{
    note = "gut";
}
else
{

switch case

Einen Wert mit festen Möglichkeiten vergleichen.

Mit switch vergleichst du einen Wert mit mehreren festen Möglichkeiten. Es ist eine übersichtliche Alternative zu einer langen Kette aus else if, wenn immer dieselbe Variable auf Gleichheit geprüft wird.

Pseudocode
FALLS tag
    1 BIS 5: AUSGABE "Arbeitstag"
    6, 7:    AUSGABE "Wochenende"
    SONST:   AUSGABE "Ungültiger Tag"
ENDE FALLS
C#
int tag = 6;
switch (tag)
{
    case 1:
    case 2:
    case 3:
    case 4:
    case 5:
        Console.WriteLine("Arbeitstag");
        break;
    case 6:
    case 7:
        Console.WriteLine("Wochenende");
        break;
    default:
        Console.WriteLine("Ungültiger Tag");
        break;
}
  • switch (tag)Der Wert in der Klammer wird mit den Fällen verglichen.
  • case 6:Ein möglicher Wert. Der Doppelpunkt gehört dazu.
  • break;Beendet den Fall. Ohne break gibt C# eine Fehlermeldung aus.
  • default:Läuft, wenn kein Fall gepasst hat. Wie das else bei if.
  • Mehrere FälleStehen case Zeilen direkt untereinander, teilen sie sich denselben Code.

Schleifen im Überblick

Wozu Schleifen, welche Arten es gibt und was kopf und fußgesteuert heißt.

Stell dir vor, du sollst »Hallo« hundertmal ausgeben. Du könntest hundert Zeilen tippen. Mit einer Schleife schreibst du es einmal und sagst dem Programm, wie oft es laufen soll.

for (int i = 0; i < 100; i++)
{
    Console.WriteLine("Hallo");
}

Jede Schleife besteht aus drei Dingen

  • StartwertWomit beginnt die Schleife? Zum Beispiel int i = 0;
  • BedingungWann läuft sie weiter? Solange sie wahr ist, wird wiederholt.
  • VeränderungEtwas muss sich ändern, sonst endet sie nie. Zum Beispiel i++.

Die vier Schleifen in C#

SchleifePseudocodeWann
whileSOLANGEDu weißt nicht, wie oft. Die Bedingung wird vor jedem Durchlauf geprüft.
do whileWIEDERHOLE BISDer Block läuft mindestens einmal. Die Bedingung wird nach dem Durchlauf geprüft.
forFÜRDu weißt, wie oft. Es gibt einen Zähler.
foreachFÜR JEDENDu gehst jedes Element einer Liste durch.

Kopfgesteuert und fußgesteuert

Entscheidend ist, wo die Bedingung geprüft wird. Danach heißen die Schleifen:

KopfgesteuertFußgesteuert
Bedingung stehtOben, vor dem BlockUnten, nach dem Block
Block läuft mindestensNullmal. Ist die Bedingung gleich falsch, läuft nichts.Einmal. Der Block läuft immer zuerst.
C#while und fordo while
Typisch fürZählen, Suchen, Warten auf ein EreignisEingabe prüfen und wiederholen
MerkbildKopfgesteuert prüft erst und läuft dann. Fußgesteuert läuft erst und prüft dann.
WIEDERHOLE BIS ist umgekehrt Im Pseudocode endet WIEDERHOLE BIS, wenn die Bedingung wahr wird. In C# läuft do while weiter, solange die Bedingung wahr ist. Wer Pseudocode in C# umsetzt, dreht die Bedingung also um. Aus BIS zahl >= 1 wird while (zahl < 1).

Endlosschleife

Wird die Bedingung nie falsch, hört die Schleife nie auf. Das Programm hängt. Meist fehlt die Veränderung, zum Beispiel i++. Mit Strg und C beendest du das Programm in der Konsole.

int i = 0;
while (i < 5)
{
    Console.WriteLine(i);
}

Hier bleibt i immer 0. Die Bedingung ist immer wahr.

while Prüft vor dem Block
do while Prüft nach dem Block
for Mit Zähler, feste Anzahl
foreach Jedes Element einer Liste
Jede Schleife braucht einen Startwert, eine Bedingung und eine Veränderung.

while

Die kopfgesteuerte Schleife: erst prüfen, dann laufen.

Die while Schleife prüft die Bedingung vor jedem Durchlauf. Stimmt sie, läuft der Block. Danach wird wieder geprüft. Sie ist kopfgesteuert. Du nutzt sie, wenn du nicht vorher weißt, wie oft etwas wiederholt wird.

Beispiel: Du sparst auf ein neues Handy. Es kostet 150 Euro. Du hast schon 100 Euro und legst jeden Monat 20 Euro zurück. Nach wie vielen Monaten kannst du es kaufen?

Pseudocode
kontostand ← 100
monate ← 0
SOLANGE kontostand < 150
    kontostand ← kontostand + 20
    monate ← monate + 1
ENDE SOLANGE
AUSGABE monate
C#
int kontostand = 100;
int monate = 0;
while (kontostand < 150)
{
    kontostand = kontostand + 20;
    monate = monate + 1;
}
Console.WriteLine(monate);

Schritt für Schritt durchklicken

Klicke dich durch. Rechts siehst du, wie sich die Werte nach jeder Zeile verändern.

Schritt für Schritt durchklicken
int kontostand = 100;int monate = 0;while (kontostand < 150){    kontostand = kontostand + 20;    monate = monate + 1;}Console.WriteLine(monate);
  • Prüfen zuerstAuch beim ersten Mal. Stimmt die Bedingung gleich nicht, läuft der Block kein einziges Mal.
  • Etwas muss sich ändernIm Block muss eine Variable verändert werden, die in der Bedingung steht.
  • Danach geht es weiterIst die Bedingung falsch, springt das Programm hinter die Klammer.
Die zwei Fragen Frage dich bei jeder while Schleife: Was prüft die Bedingung? Und wo im Block verändere ich genau das? Fehlt die Antwort auf die zweite Frage, hast du eine Endlosschleife.

Noch ein Beispiel: Verdoppeln

Eine Bakterienkultur verdoppelt sich jede Stunde. Sie startet mit einem Bakterium. Wann sind es mehr als 1000?

int bakterien = 1;
int stunden = 0;
while (bakterien <= 1000)
{
    bakterien = bakterien * 2;
    stunden++;
}
Console.WriteLine(stunden + " Stunden, " + bakterien + " Bakterien");

Nach 10 Stunden sind es 1024 Bakterien. Die Schleife läuft genau zehnmal.

do while

Die fußgesteuerte Schleife: erst laufen, dann prüfen.

Die do while Schleife führt den Block aus und prüft die Bedingung erst danach. Sie ist fußgesteuert. Der Block läuft deshalb mindestens einmal. Typisch ist eine Eingabe, die so lange wiederholt wird, bis sie passt.

Pseudocode
WIEDERHOLE
    EINGABE zahl
BIS zahl >= 1 UND zahl <= 10
AUSGABE "Danke"
C#
int zahl;
do
{
    Console.Write("Zahl von 1 bis 10: ");
    zahl = int.Parse(Console.ReadLine());
}
while (zahl < 1 || zahl > 10);
Console.WriteLine("Danke");
Bedingung umdrehen Im Pseudocode steht, wann die Schleife endet: BIS zahl >= 1 UND zahl <= 10. In C# steht, wann sie weiterläuft: while (zahl < 1 || zahl > 10). Das ist genau das Gegenteil. Aus UND wird dabei ODER.

  • SemikolonHinter while (...) am Ende steht bei do while ein Semikolon. Bei der normalen while Schleife nicht.
  • Variable vorher anlegenzahl muss vor dem do stehen, sonst kennt die Bedingung sie nicht.

while (true)

Den Ablauf Schritt für Schritt auf Papier nachvollziehen.

TryParse

Text sicher in eine Zahl umwandeln.

Ein Nutzer tippt alles als Text. Console.ReadLine() liefert immer einen string. Willst du damit rechnen, musst du den Text in eine Zahl umwandeln. Dafür gibt es int.Parse und int.TryParse.

Das Problem mit Parse

Console.Write("Dein Alter: ");
int alter = int.Parse(Console.ReadLine());
Console.WriteLine("Nächstes Jahr bist du " + (alter + 1));

Tippt jemand »abc« oder drückt nur Enter, stürzt das Programm mit einer Fehlermeldung ab. Der Fehler heißt FormatException.

Die Lösung: TryParse

TryParse probiert die Umwandlung. Klappt sie, liefert die Methode true und legt die Zahl in der Variable ab. Klappt sie nicht, liefert sie false. Das Programm läuft weiter.

Console.Write("Dein Alter: ");
string eingabe = Console.ReadLine();
if (int.TryParse(eingabe, out int alter))
{
    Console.WriteLine("Nächstes Jahr bist du " + (alter + 1));
}
else
{
    Console.WriteLine("Das war keine ganze Zahl.");
}
  • Rückgabetrue oder false: Hat es geklappt?
  • out int alterHier landet die Zahl. out heißt: Die Methode schreibt in diese Variable. Die Variable darf direkt im Aufruf angelegt werden.
  • ifMit dem Ergebnis entscheidest du, wie es weitergeht.
EingabeTryParse liefertalter danach
42true42
-7true-7
abcfalse0
false0
3,5false0
Kommazahlen Für Kommazahlen nimmst du double.TryParse. Mit deutscher Spracheinstellung schreibt der Nutzer ein Komma, also 3,5. Ein Punkt kann zu falschen Werten führen. Im Code selbst schreibst du Kommazahlen immer mit Punkt: double d = 3.5;.

TryParse in einer Schleife

So fragst du eine Zahl ab, bis sie wirklich passt. Das ist eine fußgesteuerte Schleife.

int zahl;
bool ok;
do
{
    Console.Write("Zahl von 1 bis 10: ");
    ok = int.TryParse(Console.ReadLine(), out zahl);
}
while (!ok || zahl < 1 || zahl > 10);
Console.WriteLine("Danke, du hast " + zahl + " eingegeben.");

Die Schleife läuft weiter, wenn die Umwandlung nicht klappt (!ok) oder die Zahl außerhalb von 1 bis 10 liegt.

Zusammenfassung
Parse Wandelt um, stürzt bei Fehlern ab
TryParse Wandelt um, meldet true oder false
out Hier landet das Ergebnis
double.TryParse Für Kommazahlen
Bei Eingaben von Nutzern immer TryParse verwenden.

Try Catch

Fehler abfangen, damit das Programm weiterläuft.

Manche Fehler lassen sich nicht vorher prüfen. Eine Datei fehlt, das Netzwerk ist weg, oder jemand will eine Pizza auf null Gäste verteilen. Dann erzeugt C# eine Ausnahme, englisch Exception. Ohne Gegenmaßnahme beendet sie das Programm. Mit try catch fängst du sie ab.

try
{
    Console.Write("Wie viele Gäste sind da? ");
    int gaeste = int.Parse(Console.ReadLine());
    int stuecke = 8 / gaeste;
    Console.WriteLine("Jeder bekommt " + stuecke + " Stücke Pizza.");
}
catch (FormatException)
{
    Console.WriteLine("Bitte eine ganze Zahl eingeben.");
}
catch (DivideByZeroException)
{
    Console.WriteLine("Ohne Gäste bleibt die Pizza ganz.");
}
finally
{
    Console.WriteLine("Guten Appetit!");
}
  • tryHier steht der Code, der schiefgehen könnte.
  • catchLäuft nur, wenn im try Block eine passende Ausnahme auftritt. Der Typ in der Klammer sagt, welcher Fehler gemeint ist.
  • finallyLäuft immer, mit oder ohne Fehler. Gut zum Aufräumen, zum Beispiel um eine Datei zu schließen.

Ein Programm mit Schleife, Verzweigung und TryParse.

Zum Schluss ein kleines Programm, das alles verbindet: Das Zahlenraten. Der Computer denkt sich eine Zahl von 1 bis 10 aus. Du rätst, bis du sie hast. Es zeigt eine Schleife, eine Verzweigung und TryParse.

Random zufall = new Random();
int geheim = zufall.Next(1, 11);
int versuche = 0;
int tipp = 0;
while (tipp != geheim)
{
    Console.Write("Dein Tipp (1 bis 10): ");
    if (int.TryParse(Console.ReadLine(), out tipp))
    {
        versuche++;
        if (tipp < geheim)
        {
            Console.WriteLine("Zu klein");
        }
        else if (tipp > geheim)
        {
            Console.WriteLine("Zu groß");
        }
    }
    else
    {
        Console.WriteLine("Das war keine Zahl.");
    }
}
Console.WriteLine("Richtig nach " + versuche + " Versuchen!");

Was hier passiert

  • Randomzufall.Next(1, 11) liefert eine Zufallszahl von 1 bis 10. Die obere Grenze zählt nicht mit.
  • whileLäuft weiter, solange der Tipp nicht stimmt.
  • TryParseFängt Eingaben wie »abc« ab. Dann bleibt tipp 0, und die Schleife läuft weiter.
  • if else ifSagt dem Spieler, ob der Tipp zu klein oder zu groß war.
Probier es aus Baue das Programm in Visual Studio nach. Erweitere es dann: Gib nach zehn Versuchen auf, oder lass den Spieler die Obergrenze festlegen.

Aufgabe 6. Schreibe ein Programm mit do while: Der Nutzer soll eine Zahl zwischen 1 und 100 eingeben. Die Eingabe wird wiederholt, bis sie passt. Verwende TryParse.

Lösung anzeigen 
int zahl;
bool ok;
do
{
    Console.Write("Zahl von 1 bis 100: ");
    ok = int.TryParse(Console.ReadLine(), out zahl);
}
while (!ok || zahl < 1 || zahl > 100);

8

Aufgabe 8. Der Code soll die Summe aller Zahlen im Array zahlen berechnen. Finde die Fehler. int summe; foreach (int z in zahlen) { summe = z; } Console.WriteLine(summe);

Lösung anzeigen

Erstens hat summe keinen Startwert, es fehlt = 0. Zweitens überschreibt summe = z den Wert bei jedem Durchlauf. Es muss summe = summe + z heißen.

int summe = 0;
foreach (int z in zahlen)
{
    summe = summe + z;
}
Console.WriteLine(summe);

Aufgabe 9. Wann nimmst du eine do while Schleife statt einer while Schleife?

Lösung anzeigen

Wenn der Block mindestens einmal laufen muss, zum Beispiel bei einer Eingabe, die geprüft und wiederholt wird.
